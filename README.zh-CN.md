# dsh-persona-memory

[English](README.md) · **简体中文**

每天跨工作区汇总会话，生长出**用户画像**、**陪伴性格**和**教训**，并把它们注入每一轮对话 —— 自带设置页，可看、可调。

## 安装

```sh
dsh plugin add github:PaangGaaSam/dsh-persona-memory
```

装完重启桌面端。没有构建步骤，没有原生依赖，也不自带 API key —— 摘要跑在宿主已配置的模型上。

打开 **设置 → 插件 → 记忆与画像**，可改调度时间、模型、预算与范围，也能立刻跑第一次摘要（「立即运行」；「强制合并自述」用来演练自述合并）。数据保存在 `$DSH_HOME/persona-memory/`，不会上传到任何地方。

要求：DSH 桌面端 + `web` 客户端平台（设置页是一个 `dsh.client` 包），Node `^22.19.0 || >=24.0.0`。

## 它做什么

1. **每天 17:00**（可配置）读取 `$DSH_HOME/sessions` 下的所有会话日志（所有工作区、窗口期内的所有会话），包括多帧 zstd 日志。
2. **第一段** —— 每个会话一张卡片：主题、用户诉求、观察（偏好 / 风格 / 思维 / 纠正 / 摩擦）、**我自己的判断**、可疑雷点（下次该改哪一步）、未解决事项。
3. **第二段** —— 把卡片合并成 `persona-memory/daily/YYYY-MM-DD.md`；我的判断直接原文落进 `## 我的判断` 区，不经过模型改写。可疑雷点写进 `## 可疑雷点`，**空答写「（无）」**。
4. **第三段** —— 把观察转成画像建议，再合并进 `profile.md`（近似去重、证据链、置顶条目受保护）。
5. **每周** —— 只拿「我的判断」当材料，用第一人称写下我的自述，收敛进 `persona.md`（我认为我是谁 / 我和你相处时的样子 / 还没想清楚的），证据规则照旧。
6. **日更末尾** —— 把当天可疑雷点 + 已有教训原文交给模型一次，代码再裁决：上限、同类合并、90 天作废、铁律转「待确认」。写进 `lessons.md`。
7. **每轮对话** —— 一个 `persona-memory` 系统提示段，顺序是 `事实（占位）→ 教训 → 画像 → 自述`。预算默认 1200 字符，基线 画像 55 / 教训 25 / 自述 20，某层用不完的额度让给被截断的层；**教训最高 40%（硬上限）**，因为它每轮都在。

## 性格如何定型

性格不是一份设定，是我在对话里形成的自述：每条都要能指回某天某场对话里发生了什么，以及我因此怎么想。所以第一段除了记录**用户**的观察，还单独记一份 **`self`：我当时的判断**（`observations` 只喂画像，`self` 只喂性格，两边不混）。

**第一人称，且不是台本。** 提示词要求每条自述走完「当时发生了什么 → 我当时怎么想 → 所以我现在倾向于怎么做」，禁止「助手应…… / 助手保持……」这类第三人称规范句，也禁止罗列语气、幽默度、称呼这类可表演的形容词。注入前还有一道代码闸门：不含「我」或仍带第三人称规范句的条目会留在文件里，但永不进提示词。旧的 `persona.md` 全是台本，因此升级后会先**静默一段时间**（不再注入旧条目），直到新的自述攒够证据 —— 这是预期行为，不是坏了。

自述先落进**还没想清楚的**，之后由**证据**推动晋级，而不是由模型的自我声明：

「我的判断」的每条都带类别：`mistake`（这一场做错了、差点做错、或被纠正后改了做法）、`stance`（对具体事情的判断，默认）、`revise`（原来那样想，现在改成这样）。只有 `mistake` 能长出可复用的行为条目，所以日报排序把它排在 12 条上限之前，persona 阶段也先看它 —— 判断「这件事怎么看」的那类记录再准，也不能重复成一条行为。

| 分区 | 晋级条件 |
|---|---|
| 还没想清楚的 (candidate) | 任何自述的默认落点；**永不注入** |
| 我和你相处时的样子 (style) | `personaMinEvidence` 个不同会话（默认 3）—— 同一天内凑够也算 |
| 我认为我是谁 (core) | 同样的会话数，**并且**满足 `personaCoreMinDates` 个不同日期（默认 3） |

两条规则保证它不跑偏：

- **重申（reaffirm）** —— 模型每轮都要先对照现有条目：同一个现象再次出现时，它用 `entry_id: "<id>"` 点名那一条，`text` 逐字照抄原文，`evidence` 只填今天的新证据。代码按 id 直接合并（不再看相似度），所以措辞怎么写都不会新开一条。没有这条时，每次改写都被当成新现象，证据永远停在 1–2 个会话，门槛也就永远够不着。
- **推翻（supersede）** —— 新自述与已定型条目冲突时，由模型点名它（`supersedes: "<id>"`）；那条的置信度降 0.3 并退回候选区，而不是与相反结论并存。鼓励自我推翻：上次那样做不成立，就写清楚为什么。
- **衰减（decay）** —— 超过 `personaDemoteAfterDays`（默认 30）天没有新证据的条目退回候选区。不删除任何东西；置顶条目永不移动。

`persona.md` **没有用户锁定区**：身份不由用户定义。用户自己定的规则属于画像的「手动锁定 / 雷区」，单独注入，不混进自述。旧文档里如果还留着 `## 用户固定规则`，它会被忽略（不删除，只是不再读写）。

证据是 `日期/会话` 形式的 token（`2026-11-10/session-7b3c4fb6`），日期取自**被引用的那一轮**（第一段提示里的 `[#n]`）而不是运行日期，所以跨午夜的会话也能正确归日。性格那一段还会读最近 `personaUpdateEveryDays` 天的日报 **`## 我的判断` 区**，因此我的自述证据可以跨天累积；改这个区的标题会让跨天证据永远为 0，核心区也就永远空着。

证据在**写入和读取两端都会被规范化**：模型回吐的无论是带轮次的 handle（`session-7b3c4fb6-5`）还是裸 uuid 片段（`c7653975-4416-4523`），都会重写成 `session-<8 位十六进制>` 并去重。否则同一场对话的两个轮次会被当成两个会话，光靠一次对话就凑满晋升门槛。旧的日报在读取时会被就地修正，不会再去污染计数。

## 教训如何积累

教训回答的是另一件事：**我上次怎么翻车的、下次具体改哪一步**。它是操作层，所以不进画像、不进自述、也不进身份块 —— 画像和自述回答「你是谁 / 我是谁」，教训回答「该怎么做」。教训常驻注入，因此必须少而硬。

| 分区 | 上限 | 衰减 | 合并 | 推翻 | 谁能增删 |
|---|---|---|---|---|---|
| 铁律 (rule) | 10 | 永不 | 不合并 | 系统不可推翻 | 只有人；**人批准才生效** |
| 时效经验 (exp) | 25 | 90 天无确认 → 作废 | 同坑重复则合并（0.85） | 可被证伪作废 | 系统只作废，人能作废 |
| 已作废 (archive) | 不限 | — | — | — | 只追加，可回看 |

**只追加、只作废，不改写。** 系统永不改写任何一条已有条目的原句：新增追加到分区末尾，失效只移动到「已作废」，原文和作废原因都留着。每次写盘前后都会对已有条目逐条比对（id / 原句 / 作用域 / 锚点），任何一条变了就拒绝写入 —— 这不是文档约定，是代码里的断言。人工「替换」是唯一允许改写的情形：必须由人在设置页点替换，旧条目照样进「已作废」留痕，新条目追加。

教训从三个入口来：

1. **每日自问** —— 日报里有 `## 可疑雷点`，可以写「（无）」。空答也是答案，面板会显示「连续 N 天空答」。
2. **后果回溯** —— 检测到后果信号（工具失败 / 用户当场纠正 / 返工 / 未解决失败）时，同一轮里回看最近三天日报原文，补认教训。
3. **用户兜底** —— 对话里说「记一下」就自然抽成候选，随日报落盘。没有新增工具。

**模型给建议，代码裁决。** 模型只写「下次该改哪一步」和分区建议；代码决定上限、合并、作废，以及**所有新铁律先进「待确认」**，人点「批准」才生效。分区看失效条件：成立条件依赖任务属性（规模、可逆性、破坏性）→ 铁律；依赖环境属性（版本、路径、API 形状）→ 时效经验。铁律还要过一道自检：**违反它会不会造成不可逆后果？** 只是返工就不够格。

**冲突检测归系统，处理归性格。** 同一作用域下两条语义相反的条目（一条「必须」、一条「不要」，且说的是同一件事）会被机械扫描标成 `[冲突]`，面板可见、注入行也带着标记 —— 但代码不裁决，也不删任何一条。怎么处理交给自述；现阶段自述还是空的，所以默认行为是**动手前先问一次**（注入里那一行软默认），等自述长出来自然被覆盖。

作用域 v1 只有两档：**当前工作区（cwd）** 和 **全局**。别的 worktree 的教训不会进这个工作区的提示词。教训还带锚点（日期 / 会话 / 日报里那句话），指向的日报条目被删时，教训保留，面板把锚点显示成「（原条目已删除）」。

## 事实层（按需检索，不进提示词）

教训回答「该怎么做」，事实回答「是什么」：装在哪、版本多少、路径怎么走、当时定过什么。两层刻意相反 —— 教训常驻注入，所以要少而硬；事实**从不进提示词**，只在模型调用 `facts_search` 时按关键词检索。所以事实库可以一直长，而每轮提示词的字符数不变。

- 文件 `$DSH_HOME/persona-memory/facts.md`：**只追加、只作废、不改写**。每次写盘前后逐条比对 id / 原句 / 作用域 / 验证命令，任何一条变了就拒绝写入；作废必须给原因，原句和 `[验证]` 一起进「已作废」。
- 一条事实长这样：`- [fact-1] [作用域 本机] [确认 2026-11-12] DSH 装在 D:\deepseekharness（锚点：…）`，下面可以跟两行续行：`  [验证] Test-Path …`（一行命令，现场自证）和 `  [回注] …`（可选，v1 只存不用）。续行是缩进的独立行，所以命令里带方括号也不会把解析弄坏。
- 作用域三档：**全局 / 本机 / 工作区路径**。检索只带全局 + 本机 + 当前工作区；别的工作区的事实只报「另有 N 条只属于别的工作区」，不注入、不混进来。
- 过期：超过 **180 天**没再确认的条目标 `[可能过期]`，但**不删除、不隐藏**；面板上点一次「确认」就刷新日期。
- v1 **只有人能写**：设置页「事实」卡片，或者 `POST /persona-memory/facts/add`。没有一个叫 `facts_add` / `facts_archive` 的模型工具 —— 模型能调用的只有 `facts_search`，所以「事实不改写事实」在代码里是真的。
- 没命中时工具直接返回「没有找到…不要据此推测」，不让模型拿空结果编。

## 设置页

插件带一个浏览器半身（`dsh.client`），在宿主设置里注册「**记忆与画像**」分区。它显示运行状态，可改调度、模型、预算与范围，可手动跑摘要（可强制合并自述），可逐条置顶 / 取消置顶，可回滚到写入前的备份，也能读最新一篇日报。

「我的自述」卡片会直接告诉你**当前注入了几条**（以及注入段是否为空）。文件和提示词是两回事：候选区写得再满也不注入，所以看到「当前注入为空」时，卡片会顺带说明还差多少证据 —— 不用去翻代码或日志。

画像和自述卡片**都**默认每区只列 **3 条**（置顶的排最前），末尾一行「展开全部（N）」可以摊开；「手动锁定」区不折。排序是置顶 → 最后验证时间 → 置信度，所以被折叠的条目展开后就能置顶，不会出现「想置顶却看不到它」。折叠只影响面板显示，**和注入多少条完全无关**。

「教训」是一张独立卡片（不塞进画像里）：列出铁律 / 时效经验 / 已作废，每条带作用域、锚点、最后确认日，冲突和「待确认」都有标记。可以手动新增（选铁律还是时效经验）、否决（作废必须填原因）、替换（只有铁律，且要点两次确认）；「批准」只对待确认的铁律出现。卡片还会显示**连续空答天数**、**待确认铁律条数**，以及**当前注入了几条**（和自述那句同一个口径）。它只展示这些数字，不会替你做任何决定。

下面配置块里的每一个开关都能在页面上改 —— 包括「我认为我是谁」的日期门槛和降级天数 —— 补丁行不再是非用不可的唯一入口。每个字段都带一行说明，讲清它改的是什么；能校验的都会在发请求前校验（时间格式、数值范围）：填错时控件下方直接显示原因，并禁用「保存」。**保存成功后表单显示的是刚写进磁盘的值** —— 页面会拿保存后重新读到的配置回填，不会把你改的那一栏打回旧值。时间允许全角输入（`23：00`、`２３：００`）：输入时就地归一化成 `23:00`，`23:0` / `23` / `23:00:00` 仍然报错。**提供方和模型是下拉框**，选项来自宿主自己的模型目录（`ctx.llm.listProviders()` / `listModels()`，经 `GET /persona-memory/models` 送出）；控件用 `color-scheme: inherit`，所以闭合框和原生弹出列表都跟随宿主解析出的深/浅色方案。某个适配器列不出模型时，这两个字段退回手填输入框；已经保存的值永远保留在选项里，所以打开页面绝不会悄悄改掉它。

在这里做的设置会以覆盖项存进 `persona-memory/config.json`，优先级高于补丁行配置；删掉该文件即回落到补丁行。设置页直接调插件自己的回环路由，不经过宿主的设置管道。

### 身份块（画像的派生视图）

「身份块」不是第二个记忆：它读 `profile.md`，让模型归纳五个字段 —— **角色 / 领域 / 技术栈 / 工作流 / 印象**，每条一句判断，依据只记在 `basis`（被引用条目的 id）里，主行不写推理链。它允许而且要求外推：从「在意权限边界 + 要求来源 + 先讲清再动手」可以直接落到「大概率在做运维或平台工程这类会被事故追责的活」，而不是罗列「这三样反复出现，我猜……」。禁止推断健康、宗教、政治、性取向、经济状况、婚恋。

三条硬约束：

- **只喂置信度 ≥ 0.7 的条目**，置顶 / 手动锁定的条目无条件计入；被滤掉的条数会显示成「另有 N 条低于阈值未计入」。
- **版本没变就不重算**：缓存 `identity.json` 里记着 `profileVersion`，画像没动过的日子不会产生任何模型调用。
- **永不写回画像、永不进提示词**：它不能变成条目（否则推断会被下次合并当证据，形成自我强化的回路），`lib/inject.js` 也不认识它。面板只提供「重新生成」一个动作，没有手改入口；生成失败时保留上一次缓存，不清空、不留半截。

### 运行通知

页面开着时每 30 秒轮询一次 `/persona-memory/status`。出现新的一次运行就在页面顶部弹一条横幅：时间、会话数、卡片数、画像 / 自述增量，以及自述条目晋升 / 降级 / 推翻了几条。自述合并失败时横幅会直接给出原因（文件不动、原文进日志），而不是显示成「没有新条目」。横幅总是有；勾上**运行通知**会额外申请桌面系统通知，**测试系统通知**用来探测当前 shell 是否放行。页面关闭时不推送任何东西 —— 宿主没有通知服务可挂。

运行记录本身携带结果（`profile`、`persona`、`lessons`（含 `truncated` 与 `suggestions`）、`skipped`、`error`），所以横幅不需要解析日志。

### 模型回答被截断时

模型偶尔会在句子中间断掉（流被掐断、接近超时），返回的 JSON 不闭合。这种情况**不再算作成功**：

- 残片里已经写完整的条目照常收下 —— 条目本身是合法 JSON，只是外层 `{"add":[` 没写完；收条时不因为「整段不完整」把好的条目一起丢掉。
- 日志里写一条 `warn`：`lessons truncated: 1437 chars in 140032ms, kept 1 suggestion(s)`。长度和耗时放在同一行，下次好判断是模型写坏了还是流被掐断（默认超时 180 秒）。
- 运行摘要和页面横幅都会写明「本次输出被截断，只收下 N 条」，而不是显示成「没有新的可写条目」。
- `{"add":[]}` 仍然是合法答案（今天确实没有可写的），不报警。

## 工具

| 工具 | 用途 |
|---|---|
| `persona_digest` | 立刻跑一次摘要（`force_persona: true` 强制合并自述） |
| `persona_profile` | 读取画像与自述的 markdown |
| `persona_status` | 调度、上次运行、文件大小 |

| `persona_note` | 把一条用户口述的规则追加到锁定区 |
| `facts_search` | 按关键词检索事实（全局 + 本机 + 当前工作区），返回锚点与验证命令；**不注入提示词，只有它读事实** |

## 数据布局

```
$DSH_HOME/persona-memory/
├── profile.md            # 用户画像（唯一事实来源）
├── persona.md            # 我的自述（第一人称；旧标题会被识别并改写）
├── lessons.md            # 教训（铁律 / 时效经验 / 已作废；只追加、只作废）
├── facts.md              # 事实（全局 / 本机 / 工作区；按需检索，不进提示词；只追加、只作废）
├── identity.json         # 身份块缓存（画像的派生视图，只读不写回）
├── config.json           # 设置页覆盖项（可选）

```

## 限制

- 定时时刻需要宿主进程在跑。错过的那一次**不回跑**：下次启动只把游标移到下一个未来时刻，错过的那次在 `logs/run-<day>.jsonl` 里留一条 warning。准点触发但跑失败的也不会重试，失败留在日志和 `lastError` 里。
- 池子上限（铁律 10 / 时效经验 25）限制的是 `lessons.md` 里**装多少条**，不是提示词里**读多少条**：教训层仍按字符预算截断，设置页会显示有多少条因预算没进提示。池子变大等于新经验不再掉进日报，而不是每条都会进提示。
- 模型输出必须是 JSON；解析容忍散文和代码围栏，但某一段生成失败只降级那一段（其余段照常写入）。
- **作用域 v1 只认宿主给的 cwd**：宿主目前没有确认「每轮重建提示词」，所以 `buildSectionText` 先取上下文里的 `cwd`，取不到就用宿主进程的 cwd。结果是**全局教训总会注入**，工作区教训只有在宿主进程就跑在那个工作区时才注入。关键词 / 文件类型匹配留空不实现 —— 宁漏勿滥。
- 教训的冲突检测是机械扫描（同作用域 + 极性相反 + 文本相似度 ≥ 0.4），不是语义理解：它会把明显相反的标出来，也可能漏掉绕了一圈的表达。标错不会删任何东西。
- 事实检索是关键词匹配（子串 + 分词命中），不是语义检索：换个说法就可能搜不到。宁漏勿错 —— 没命中时它直接说没记录。检索结果会作为工具结果进入这次对话，因此下一次日更会读到它（stage-1 已有「不把系统技术结论写进 self」的约束，`isSystemFactObservation` 再把系统类事实挡在画像之外）。
- 以 `link:` 安装的包，改源码后需要重启宿主（加载器不热重载软链接源码，客户端 bundle 是从构建好的 `lib/client.js` 直接发出的）。
